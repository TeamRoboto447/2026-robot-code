# Turret Lookup Table Generator

> **Architecture change (March 2026):**
> The real-time shot solver has been moved onto the roboRIO. The RIO now loads
> `turret_data.json` at startup from the deploy directory, interpolates it in
> memory, and runs the Newton-method dynamic-shooting solver every 20 ms — no
> coprocessor round-trip.
>
> **`lookup_table_handler.py` is no longer part of the real-time aiming loop.**
> It can still be run as a visualisation/diagnostics tool, but the RIO ignores
> the values it writes to NetworkTables.
>
> **The only file that needs to be kept up to date is `turret_data.json`.**
> After adding or editing data points (option 1), copy the file to the deploy
> directory and redeploy to the RIO:
> ```bash
> cp turret_data.json ../src/main/deploy/turret_data.json
> ```
> Then deploy with `./gradlew deploy` as normal.

Quick reference for collecting empirical static data points and re-exporting
`turret_data.json` for the on-RIO solver.
A known-good `turret_data.json` is already committed — no new data collection needed unless re-tuning.

---

## 1. Activate the Virtual Environment (Windows Laptop)

Open a terminal in the project folder, then run:

```bat
venv\Scripts\activate
```

You should see `(venv)` appear in your prompt. Then install dependencies if needed:

```bat
pip install -r requirements.txt
```

---

## 2. Collect / Edit Static Data Points

Start the generator:

```bat
python turret_lookup_generator.py
```


---

## 2. Collect / Edit Static Data Points

Start the generator:

```bat
python turret_lookup_generator.py
```

### Step 1 — Collect static data points (option 1)

Drive the robot to each test distance, tune until shots go in, and save each point.
Record the actual `flight_time` in seconds if possible — the `2.5 s` placeholder
values will cause wrong lead calculations while moving.

### Step 2 — (Optional) Preview / export (options 4 & 5)

The `lookup_table.json` generated by options 4-5 is **no longer used by the robot**.
You can still generate it for visual inspection, but the RIO uses `turret_data.json`
directly.

---

## 3. Deploy Updated Data to the RIO

After saving new data points, copy `turret_data.json` into the deploy directory
and redeploy:

```bash
cp turret_data.json ../src/main/deploy/turret_data.json
```

Then from the repository root:

```bash
./gradlew deploy
```

---

## 4. Tuning Notes

### Static shots off
Collect new data points at the relevant distances (option 1). Stationary accuracy
depends entirely on the data points — the on-RIO solver interpolates between them.
More points = smoother interpolation.

### Shots off only while moving
The on-RIO Newton solver accounts for robot velocity automatically. The dominant
source of error is **inaccurate `flight_time` values** in `turret_data.json`. Measure
actual flight times and replace the `2.5 s` placeholders.

### IF YOU NEED TO RETUNE `turret_data.json`
- Make a backup of the current one
- Choose option 1 (collect new data point) and follow its prompts
  - Repeat for as many data points as needed (4-5 recommended)
- Copy to deploy directory and redeploy (see section 3 above)
